## 一、产品定位

**闪念** = 自媒体内容创作平台，双账号小团队（峰岚 / 佳韵）使用。

- 所有工具存在的目的：**为内容创作提效**，不是增加使用理解成本
- 页面模块多，所以更要**简单化、不要复杂化、不要工具化**——术语用创作者语言（拍什么 / 写什么 / 发出去），不炫技
- 产品主张：捕捉闪念 → 沉淀灵感 → 凝练选题 → 结构脚本 → 生产文案 → 发布 → 数据复盘 → 沉淀知识图谱，一条创作闭环

### 全局设计原则

1. 一级导航常驻 ≤ 11 图标，后续新增模块只进「更多」，Dock 永不膨胀
2. 导航顺序即创作工作流顺序
3. 最高频动作（闪念快记）永远单触点直达：PC 按 N 键 / APP 独立快记球
4. 信息层级：关键数字是视觉焦点，彩色图标置于标题左侧
5. 全局禁止 Emoji 图标
6. UI 组件基于 shadcn/ui（Base-UI 底层 Rhea 预设），非明确需求不得擅改
7. **全局没有删除功能**，一切内容只能归档（归档是唯一终态）
8. 详情页只读：内容创建后不可编辑，除各模块文档明确允许的编辑场景
9. 页面呼吸感：区块间距 24 / 卡片内边距 20 / 行高 1.5 / 每屏至少 1/4 留白

## 三、全局规则（所有模块共同遵守）

1. 负责人=动态注册账号：选项来自系统当前注册账号列表（当前 2 人，**峰岚/佳韵为演示占位昵称**，后续新增账号即新增选项）；头像色按注册顺序从预设色板分配（占位：峰岚=蓝紫 99,102,241、佳韵=红）
2. 待办优先级 P0~P3，描述：必须干完 / 应该干完 / 本周内 / 有空再做；小注「默认 P2 · 按截止自动升阶」
3. 关联模块仅 3 个：对标拆解 / 选题库 / 制作发布（进度目标数：选后必填，单位「条」）
4. 跨模块转化一律快照拷贝独立编辑，源记录更新不互相影响；**转化只能一次（去向二选一），转化后源记录状态统一为「已转化」**（紫 139,92,246）；转化不减、内容不删
5. 状态色统一映射主题 token（见 L3），禁止模块自定色系
6. 全局无删除；当天完成 23:59 自动归档
7. 双端并行设计：PC 1920 宽 / APP 390 宽，均自动布局、高度 HUG
8. 消息通知是独立模块：各模块的关键流转自动产生消息（待办创建/接受、选题转生产、闪念超 48h 提醒等），汇总进消息页，Topbar 铃铛带未读数
9. **分配通知**：所有含「负责人」的记录，创建/改派负责人时立即给该负责人发分配消息（例：「这条对标拆解由你来负责」）
10. **进度统计按负责人过滤**：待办关联模块的进度只统计**该待办负责人名下**的关联记录（待办「佳韵拆 10 条对标」不计峰岚名下已拆解的记录）
11. **归档语义区分**（待逐条过确认）：库类资源（脚本框架/常用标签）归档=停用，可恢复启用；记录类内容（闪念/灵感/选题/发布/复盘/对标拆解）归档=终态不可逆
12. **视图规则**（2026-08-31 确认）：内容模块默认「列表卡片视图」**起步**（一记录一横向卡片，卡片内不嵌表格），其他视图（看板/日历/表格）等 P0 落地后**按需后补**；例外 4 处为模块固有形态：闪念池=星图+列表双视图、知识图谱=图谱视图、数据追踪=图表+表格、首页工作台=仪表盘混合卡

## 六、技术栈

| 层 | 技术 |
|---|---|
| 端形态 | PC = Tauri 2 桌面应用 / 移动端 = PWA（Vercel 部署，可安装、离线可用） |
| 前端 | Next.js 16 + React 19 + TypeScript + Tailwind CSS v4 + shadcn/ui（Base-UI 底层，**视觉以 Pixso 设计为准**）+ Zustand |
| 本地优先 | Dexie.js（IndexedDB）：离线可读写，数据先落本地 |
| 云端 | **Turso（libSQL，免费 5GB）**——2026-08-31 确认，不用 Supabase；**知识图谱同库存储（节点表+边表+递归查询，不用 Neo4j）** |
| 认证 | Auth.js（Credentials Provider）：双账号预建，无注册页；签发 JWT 存 httpOnly cookie |
| 文件存储 | Cloudflare R2（10GB 免费，**出站流量永久免费**）；数据库只存文件 URL |
| 同步策略 | **近实时**（非 Realtime）：写入即推 + 按 `updatedAt` 游标增量拉（页面聚焦 / 每 60 秒触发）；冲突 = 记录级最后写入胜出，**但「转化」操作须幂等去重，不能只靠 LWW** |
| 同步提示 | 轻量三件套：Topbar 同步状态点（青绿=已同步 / 旋转=同步中 / 灰+数字=待同步 N 条）+ 设置页数据分组（上次同步/待同步数/手动同步）+ 断网顶部细条「离线模式，数据已存本地」 |
| 本地 AI | Ollama 纯 CPU 推理（i7-10700 / 16GB / 无独显：0.5b~8b Q4 可跑；deepseek-r1:7b 思考链 CPU 上 2~5 分钟，倾向并入 qwen3:8b 低温度——17 模块文档逐条过定）。**2026-08-31 确认：AI 与语义向量检索延后，不纳入本阶段**；仅 PC 端可用（PWA 移动端访问不到本机 Ollama） |
| 部署 | GitHub + Vercel；PC 桌面壳 Tauri 2 打包 |

**工程铁律**：本仓库的 Next.js 与常见版本约定不同（见根目录 AGENTS.md），**动任何代码前必须先读 `node_modules/next/dist/docs/` 相关文档**，禁止凭训练记忆写代码。

## 十、文档使用规则（每次开工读什么）

1. 设计开工：先读本总纲 → 对应模块文档 → L3 视觉规范；字段值以模块文档为准
2. 代码开工：先读根目录 AGENTS.md 与 `node_modules/next/dist/docs/` 相关章节 → 本总纲第六/七节 → 对应模块文档
3. 验收核对：总纲第九节故事线数据 → 画板截图逐项对照
4. 规则变更：先改文档再改画板/代码，保持三者一致
